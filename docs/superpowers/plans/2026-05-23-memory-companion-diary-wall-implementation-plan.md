# Memory Companion Diary Wall Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the standalone `我来写` path, turn `请她写` into a companion-first `日记墙`, keep journal generation as both an automatic daily artifact and a manual regenerate/refresh action, add a daily OOTD entry generated by her, and restore daily greetings as background-generated content that the user sees when they return and opens through a typewriter-style reveal.

**Architecture:** Consolidate the current split `WritePage` and `AskHerPage` mental model into a single diary wall domain. The wall becomes the main companion content surface and renders multiple companion-authored entry types: `daily_journal`, `daily_ootd`, and `daily_greeting`. Backend orchestration should pre-generate daily entries on schedule or on login catch-up, while the frontend offers manual journal refresh/regeneration without reintroducing a separate self-authored flow.

**Tech Stack:** React 18, Vite, TypeScript, Vitest, Express, better-sqlite3, existing companion domain, existing generation task pipeline, existing journal/media generation services

## Product Direction

- Delete the `我来写` entry and page completely.
- Keep journal generation, but make it live inside `日记墙`.
- Support both:
  - automatic daily journal generation
  - manual regenerate/refresh by the user
- Add `每日OOTD` as a new daily companion artifact.
- Re-enable `每日问候`, but generate it in the background and surface it when the user next logs in.
- Greeting open behavior should feel like receiving a message:
  - user sees a waiting greeting card
  - user clicks it
  - text appears in a typewriter-like reveal

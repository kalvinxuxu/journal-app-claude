# 首页导航精简与照片墙设计

**目标**：精简首页与导航中的重复入口，移除低价值的独立语音页，新增“照片墙”产品入口，并统一优化图片生成方向，使照片更偏全身、竖屏、夜间睡衣感。

**范围**：
- Web 前端信息架构与页面入口
- 照片墙页面与视觉样式
- 图片生成提示词策略
- 夜间加餐自拍提示词策略

**不包含**：
- Mobile App 同步改造
- 后端路由结构大改
- 新引入图像处理服务

---

## 1. 背景与问题

当前 Web 端存在 5 个明显问题：

1. 顶部导航和首页 Hero 区重复出现 `我来写 / 请她写 / 语音页` 等入口，用户会感觉界面冗余。
2. 独立 `语音页` 已经没有核心必要性，实际语音能力已经可以附着在日记卡片里。
3. 所有历史日记里生成过的图片缺少统一归集入口，沉淀价值没有被产品化。
4. 夜间加餐自拍的提示词不够稳定，导致晚间照片不够贴近“睡衣、慵懒、亲密夜晚”的目标风格。
5. 目前图片更容易生成半身或近景图，缺少“全身、竖屏、日常抓拍/写真感”的稳定导向。

---

## 2. 设计目标

本轮改动以“收口入口、增强沉淀、统一审美控制”为目标。

### 核心目标

1. 页面主导航只保留一组核心入口。
2. 语音功能回收至日记卡片，不再保留空心页面。
3. 新增照片墙，让图片内容可浏览、可回看、可沉淀。
4. 照片墙视觉上形成明确差异化，采用拍立得冲洗照片语言。
5. 所有图片生成统一偏向：
   - 全身照优先
   - 竖屏优先
   - 更强生活场景感
6. 夜间照片统一偏向：
   - 睡衣感
   - 慵懒感
   - 轻性感但不裸露

---

## 3. 信息架构调整

### 调整前

当前主导航：

- 首页
- 我来写
- 请她写
- 语音页
- 设置

首页 Hero 区还包含：

- 我来写
- 请她写

这导致：

- 同类动作入口重复
- 语音页存在但价值偏弱
- 缺少“照片资产入口”

### 调整后

新的主导航固定为：

- 首页
- 我来写
- 请她写
- 照片墙
- 设置

### 设计原则

1. “写”和“请她写”是主动作，保留在主导航。
2. “语音页”删除，因为它不再构成独立任务闭环。
3. “照片墙”升级为一级入口，因为它承载长期沉淀价值。
4. 首页 Hero 区不再重复放 `我来写 / 请她写`，避免导航信息重复。

## 4. 页面级设计

## 4.1 首页

### 调整内容

- 保留：
  - 月份概览
  - 卡片流 / 月历切换
  - 日记列表
  - 当前选中日记内容
- 删除：
  - Hero 区里的 `我来写`
  - Hero 区里的 `请她写`

### 目标效果

首页变成“浏览与回看中心”，而不是重复分发动作按钮的二级导航层。

### 预期收益

- 降低视觉噪音
- 避免用户对入口层级困惑
- 把首页重点重新放回“看内容”

## 4.2 语音页

### 处理方式

- 删除独立 `VoicePage`
- 从主导航移除 `语音页`
- 保留已有的日记内语音播放能力

### 新语音策略

语音能力仅出现在：

- 日记卡片中的语音条
- 日记内容相关的语音展开区

### 原因

独立语音页当前没有形成独立闭环：

- 没有比卡片内播放更高的效率
- 没有更强的归档或筛选价值
- 增加了无效导航层级

因此不再保留独立页面。

## 4.3 照片墙

### 页面定位

照片墙是一个“历史图片沉淀页”，用于统一展示所有日记中生成过的照片，包括：

- `journal.images`
- `journal.selfies`
- `journal.nightBonusSelfie`

### 数据来源规则

每一篇日记的可展示图片都要被收集到照片墙中。

归集优先级：

1. 常规图片 `images`
2. 自拍图 `selfies`
3. 夜间加餐图 `nightBonusSelfie`

每张图在照片墙中要保留基础元数据：

- 来源日记 id
- 日期
- 心情
- 图片类型：`image / selfie / nightBonus`
- 原始图片地址

### 展示形式

照片墙采用“拍立得冲洗照片”视觉：

- 宽白边相纸边框
- 底部留更宽留白
- 轻微暖色偏黄
- 轻微褪色和柔光
- 微颗粒
- 少量轻微旋转，形成手工贴墙感

### 页面体验

- 默认瀑布/网格式浏览
- 点击单张可查看大图
- 卡片上可显示日期与心情标签

### 视觉目标

不是做“技术图库”，而是做“恋爱记忆墙”。

## 5. 图片风格控制设计

## 5.1 全局图片生成方向

当前图片生成提示词需要更明确约束。

### 新目标

所有常规图片优先满足：

- 竖屏照片
- 全身照或至少大半身到全身
- 真实生活摄影感
- 更像随手拍、写真、日常记录
- 场景完整，不只给面部特写

### 提示词层面的强化点

需要在图片提示词中强化以下语义：

- full-body portrait
- vertical composition
- subject fully visible in frame
- natural pose
- complete outfit visible
- real-life candid fashion/lifestyle photography

### 应避免的结果

- 近距离脸部特写
- 只到胸口的上半身图
- 背景极少、信息不足的头像式构图

## 5.2 夜间加餐图片方向

### 新目标

夜间图要更稳定地产出：

- 睡衣照
- 夜晚房间场景
- 慵懒、亲密、晚安氛围
- 轻性感
- 但不裸露、不色情、不失真

### 风格边界

允许：

- 黑色丝袜
- 性感但不打擦边的黑丝睡裙
- 居家床边/窗边/镜前/沙发边场景
- 微湿发、夜灯、柔和阴影
- 轻微挑逗
- 轻微裸露


### 预期关键词方向

- pajama
- nightwear
- bedtime atmosphere
- intimate indoor evening portrait
- soft warm lamp light
- relaxed full-body vertical portrait

## 6. 数据模型设计

现有 `Journal` 数据结构不必大改。

### 保持不变

- `images?: string[]`
- `selfies?: string[]`
- `nightBonusSelfie?: string`

### 新增派生视图模型

建议在前端页面层生成统一的照片墙视图对象，而不是先改后端主数据结构。

建议新增派生类型：

```ts
type PhotoWallItem = {
  id: string;
  journalId: string;
  date: string;
  mood: Mood;
  kind: "image" | "selfie" | "nightBonus";
  src: string;
};
```

### 原因

- 不破坏现有持久化结构
- 不影响后端接口兼容性
- 更适合先快速产品化

## 8. 测试与验收标准

## 8.1 导航验收

- 顶部导航只出现一组主入口
- 首页不再重复出现 `我来写 / 请她写`
- 顶部导航中不再出现 `语音页`
- 顶部导航中出现 `照片墙`

## 8.2 语音能力验收

- 独立语音页入口消失
- 日记卡片中的语音播放仍可用
- 日记内语音文稿仍可查看

## 8.3 照片墙验收

- 所有历史 `images / selfies / nightBonusSelfie` 都会出现在照片墙
- 无图日记不会生成空卡片
- 照片墙中可区分图片类型
- 视觉上有明显拍立得风格

## 8.4 图片风格验收

- 新生成图片多数为竖屏
- 新生成图片多数为全身或大半身偏全身
- 夜间图片明显更靠近睡衣、晚间室内、慵懒风格

---

## 9. 风险与约束

### 风险 1：提示词增强后，生成结果仍然波动

原因：

- 上游模型本身存在随机性

应对：

- 通过更强的构图词和场景词提升稳定性
- 不把控制寄希望于一次性绝对精准

### 风险 2：照片墙图片数量增多后页面过长

应对：

- 初版可先直接平铺
- 后续再加分组、按月筛选、懒加载

### 风险 3：删除语音页影响现有测试

应对：

- 同步清理或改写与 `VoicePage` 相关测试
- 保留语音功能本身，不保留空页面

---

## 10. 实施建议

建议分两步落地：

### 第一步

- 删除重复导航入口
- 删除独立语音页入口
- 新增照片墙页面
- 接通照片墙数据派生

### 第二步

- 强化常规图片提示词
- 强化夜间自拍提示词
- 微调照片墙视觉样式

这样可以先完成信息架构优化，再做生成质量优化，降低一次性变更风险。

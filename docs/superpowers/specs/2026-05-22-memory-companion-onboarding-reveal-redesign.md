# Memory Companion Onboarding Reveal Redesign

## Goal

把当前偏“3 道题后直接揭晓”的 companion onboarding，升级成一次更完整的首进相遇体验：

`轻注册/建档 -> 第一轮用户画像 -> 第二轮期待的她 -> 生成中 -> 揭晓 -> 命名 -> 已相遇首页`

这次改版的核心不是堆功能，而是把“她是怎么来到这里的”做得更具体、更真实、更有第一人称代入感。

## Why This Change

当前实现有几个明显问题：

1. 没有独立的轻注册/建档入口，用户直接被推入旧 onboarding。
2. 现有 3 道题过于抽象，只能得到一个模糊轮廓，难以支撑具体人物塑造。
3. 揭晓页虽然已经有立绘与文案方向，但人物仍然不够鲜活，动作和体态偏僵。
4. 文案里存在幼稚剧本腔，不符合“更真实世界一些”的目标。
5. 首进体验和早中晚问候语音、自动内容生成耦合过深，导致“遇见她”和“产品功能流”混在一起。

这让用户感受到的不是“我遇见了某个人”，而更像“我配置完了一个功能”。

## Experience Target

用户第一次进入产品时，应该明确感受到：

1. 自己先被理解，而不是先去选择一个模板女友。
2. 她的形成既来自自己的画像，也来自自己真正期待怎样的人。
3. 最终揭晓的是一个更真实、更具体、能被记住的人，而不是随机美女图。
4. 进入首页后，她和“写日记”之间的关系是自然承接的，其他功能不要抢戏。

## Primary Flow

### 1. Light Registration / Character Intake

首屏不是账号注册，也不是普通资料表单，而是一次轻注册/建档入口。

它的作用不是收集邮箱手机号，而是把用户带入“这段关系即将开始”的状态。页面应承担：

- 轻仪式感进入
- 第一人称视角氛围
- 明确告诉用户：接下来不是配置功能，而是在逐步塑造她
- 保留精致设计感的选择入口，而不是退回纯文字表单

这一页不放幼稚恋爱文案，不写悬浮剧本台词，也不堆资料字段。

### 2. Round One: About You

第一轮固定 3 题，只围绕用户自己。

题目表面要有氛围感，但底层是人格倾向建模。重点覆盖：

- 打开关系的速度，例如慢热或更容易进入状态
- 社交与心理能量方向，例如更外放或更内收
- 情绪感受与表达方式，例如敏感细腻、克制理性、直接表达

这一轮的目的不是选择她的模板，而是建立“你是什么样的人”的主轴。

### 3. Round Two: The One You Hope To Meet

第二轮比当前方案更长，也更具体。结构固定为 7 题：

- 3 题性格气质
- 2 题相处方式
- 2 题外貌与体态

其中外貌相关问题需要明确进入首版，包括但不限于：

- 发型倾向，例如长发、中长发、短发
- 身形与体态，例如纤细轻盈、匀称自然、更有存在感的成熟体态

其他问题则用于塑造：

- 气质基调，例如甜美、安静、成熟、轻傲、治愈、聪明锋利
- 靠近方式，例如主动、克制、先观察
- 表达风格，例如直白温柔、含蓄慢热、略带一点傲气
- 穿搭与整体观感，例如干净日常、温柔精致、成熟克制、轻甜可爱

这一轮的目标不是“捏人器式参数堆砌”，而是在保持真实感的前提下，让她的外貌与人格都更明确。

### 4. Matching Generation

问答结束后进入生成中页面，而不是直接跳揭晓。

这一阶段负责制造短暂但必要的停顿感，让“提交答案”转译成“她正在被拼出来”。页面可以有：

- 呼吸感动画
- 微景深或轻微位移
- 阶段性文案轮播

但不能过度游戏化，也不能用低龄幻想风表现。

这一阶段同时完成：

- 用户画像与偏好的整合
- companion personality/appearance summary 生成
- reveal 文案生成
- reveal 立绘 prompt 生成
- reveal 立绘生成与持久化

### 5. Reveal Page

揭晓页是整个首进流程的情绪峰值，必须让用户感到自己第一次真正见到了她。

命名前的 reveal 页不显示系统生成名字。页面里只使用中性称呼“她”，由用户在下一步正式命名。

页面固定包含：

1. `立绘主视觉`
   - 半写实
   - 更偏真实世界
   - 全身或接近全身
   - 穿着简单、日常、自然，不做刻意造型
   - 有轻动作和身体重心，不是僵直站姿
   - 眼神、头发、手部姿态、衣料或光影要有一点流动感

2. `一句短定义`
   - 不是标签
   - 不是系统分类
   - 是一句像真实观察的判断

3. `人物描述`
   - 像初见一个人的描写
   - 覆盖气质、说话感觉、靠近方式
   - 保留 1-2 个细节钩子

4. `相遇解释`
   - 用自然语言说明为什么像这样的她会来到这里
   - 不暴露 archetype、score、weight 等系统词

Reveal 页版式使用 `图左文右，但整体居中收窄` 的主卡布局，不做整屏横向铺满。信息区应分层明显，可用少量 bullet point 帮助阅读，但不能像系统参数表。

Reveal 页绝不使用幼稚剧本腔，也不写低龄乙游式台词。

### 6. Naming Step

用户先见到她，再给她命名。

命名不应作为冷冰冰的输入动作，而应作为揭晓后的短暂停顿：

- 先确认她已经有轮廓
- 再由用户决定怎样称呼她

这一步让“她是某个人”从系统生成变成用户关系中的正式成立。

### 7. Post-Reveal Home

进入首页后，不再把首进体验和问候语音等其他功能揉在一起。

首页只承接两件事：

1. 她已经在这里
2. 她与日记的关系开始成立

首页顶部至少体现：

- 她的名字
- 她的一句短定义
- 一个通向日记关系入口的轻文案

不应在这里堆叠早中晚问候语音或其他功能噪音。

## Question Design Rules

### Round One Rules

- 题目围绕“你是什么样的人”
- 外层文案有情绪感，但内核遵循人格测量逻辑
- 不让用户感觉自己在答制式测试题
- 不提前把焦点放到“理想型选择”
- 题目与选项都应保持居中窄栏排版
- 选项保持精致整块按钮/卡片感，不退回角落里的纯文字列表
- 每个选项文案强制压成一行；如果题意太复杂，应先改写题面，而不是让选项变成长段落

### Round Two Rules

- 题目围绕“你会被怎样的人吸引”
- 性格、相处方式、外貌都要涉及
- 外貌题可以明确，但不能低俗化、部件化、物化
- 所有选项必须服务于具体人物塑造，而不是只堆标签
- 外貌相关选项同样保持一行表达，不加副标题，不做多层解释

## Writing Style Rules

这是本次改版的硬约束。

### Universal Rules

- 全流程都不要出现幼稚剧本腔
- 不写过度二次元、低龄、悬浮台词
- 整体更偏真实世界中的理想化人物，而不是游戏角色模板
- 文案气质要跟最终人格分支绑定，而不是统一一种甜腻风格

### Personality-Specific Variation

不同类型的人物，文案应随之变化：

- `甜美可爱型`
  可以更轻、更软，撒娇感略多，但仍然像真人

- `成熟御姐型`
  更稳、更克制，可以有一点小傲气或拿捏感，但不能中二

- `安静治愈型`
  更细腻、低饱和、稳定，强调陪伴感

- `聪明冷感型`
  可以更锋利一点，但核心仍是“可以被亲近”，不能只剩高冷标签

## Visual Direction

本次视觉方向固定为：

- 半写实
- 安静
- 克制
- 真实世界感更强
- 第一人称代入更强
- 页面主体居中收束，不铺满屏幕
- 选择器件保留柔和、精致、可点击的设计感

动效原则：

- 呼吸感
- 景深感
- 微位移
- 光影流动

不采用夸张粒子、炫技 loading、低龄幻想 UI。

## Data Model Implications

这次不能只返回一段 reveal 文案，而要把“她是谁”沉淀成后续可复用的结构。

Onboarding 完成后，至少需要形成以下数据：

- `userProfileAnswers`
  第一轮 3 题答案

- `companionPreferenceAnswers`
  第二轮 7 题答案

- `companionAppearanceProfile`
  她的外貌与视觉摘要，例如：
  - 发型
  - 身形气质
  - 穿搭风格
  - 神情倾向
  - 动作/体态关键词

- `companionPersonalityProfile`
  她的性格与相处方式摘要，例如：
  - 气质基调
  - 主动程度
  - 边界感
  - 表达风格

- `reveal`
  揭晓页所需展示数据，例如：
  - 临时显示名
  - 短定义
  - 初见描写
  - 相遇解释
  - 立绘 prompt
  - 持久化立绘 URL

- `customName`
  用户命名后的正式名字

## Naming Model

命名发生在 reveal 后，因此建议使用双层名字结构：

- `systemDisplayName`
  仅用于内部生成与持久化，不在命名前的 reveal 页直接展示给用户

- `customName`
  用户命名后的正式名字，进入首页后优先使用

这样既能保证 reveal 阶段自然运转，也能确保“名字由用户来起”。

## Portrait System Direction

Reveal 立绘必须继续走真实生成链路，而不是纯占位。

但生成目标要调整为：

- 不再是一张僵硬照片式女生图
- 更接近“正在看向你的人”
- 带轻动作、姿态和氛围
- 与人物设定一致

生成成功后，这张 reveal 图要持久化，并成为后续视觉一致性的锚点，用于：

- 首页承接
- 后续自拍参考
- 人设稳定性保持

## Scope Boundaries

本次 redesign 包含：

- 轻注册/建档页
- 两轮新问答结构
- 更具体的人物生成逻辑
- 生成中状态重做
- 更自然的 reveal 页
- reveal 后命名页
- 首页首屏 companion 承接改造
- 文案语气按人格分支变化
- 外貌偏好正式进入问题结构

本次 redesign 不包含：

- 真正的账号认证体系
- 多角色切换
- 复杂角色编辑器
- 多套服装自由切换
- 揭晓阶段反复重抽
- 首进流程里的早中晚问候语音承接
- 首进流程里的其他功能堆叠

## Implementation Boundaries

需要明确拆开的旧逻辑：

- `onboarding` 与 `问候语音`
- `首进揭晓` 与 `自动早中晚问候`
- `人物塑造` 与 `当日日记生成`
- `系统临时命名` 与 `用户正式命名`

首进体验只负责：

`让她成立`

后续首页与日记负责：

`让她继续活下去`

## Success Criteria

完成后，用户第一次体验应满足：

1. 明显经历一个轻注册/建档入口，而不是直接答旧题。
2. 第一轮和第二轮清晰区分“你是谁”和“你期待怎样的她”。
3. 第二轮问题已经覆盖性格、相处方式和外貌，不再只得到抽象轮廓。
4. Reveal 出来的人物更具体、更自然，不再是僵硬随机美女图。
5. 文案整体真实、克制，不再有幼稚剧本腔。
6. 用户在见到她之后为她命名。
7. 首页承接的是她和日记的关系，而不是语音功能混入。

## Recommendation

实现优先级应为：

1. 先把首进 flow 结构彻底改对
2. 再把两轮问题与数据建模改对
3. 然后把 reveal 视觉与文案做对
4. 最后做命名页与首页承接

因为这次最核心的问题不是缺功能，而是：

`她还没有被真正塑造成一个人`

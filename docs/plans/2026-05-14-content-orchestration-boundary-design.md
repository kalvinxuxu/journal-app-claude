# Content Orchestration Boundary Design

> **Phase 5 Task 3** — Generated by brainstorming workflow, 2026-05-14.

## Goal

Define explicit boundaries between two content roles:
- **Girlfriend voice (生成层)** — produces emotionally authentic content
- **Counselor / Polish (编辑层)** — enforces safety and quality boundaries

The two layers must not blur responsibilities. Polish must not silently rewrite generation output without a traceable reason.

---

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│  Layer 1: Content Generation (女友声音)                │
│  generateJournalContent() → raw journal + voice scripts │
│  Responsible for: emotional authenticity, natural flow    │
└──────────────────────┬──────────────────────────────────┘
                       │ raw content
                       ▼
┌─────────────────────────────────────────────────────────┐
│  Layer 2: Content Polish (Counselor)                   │
│  PolishResult = negotiate(raw, constraints)            │
│  Responsible for: boundary protection, not rewriting    │
└──────────────────────┬──────────────────────────────────┘
                       │ final content + log
                       ▼
                 UI / Memory
```

---

## Layer 1: Generation (女友声音)

**Contract output:**

```typescript
type GeneratedContent = {
  journal: string;        // No length hard-limit (MiniMax generates freely)
  voiceScripts: Array<{ timing: string; transcript: string; duration: string }>;
  source: "remote" | "fallback";
  recallUsed: boolean;     // Whether memory recall contributed
  raw: boolean;            // true = unpolished, passed to Layer 2
};
```

**Responsibilities:**
- Produce emotionally natural, girlfriend-style diary entries
- Generate 2-3 voice message scripts aligned with journal mood
- Inject memory context when relevant
- Return `raw: true` to signal "needs polish pass"

**What it must NOT do:**
- Apply length constraints
- Strip sensitive content (that's Layer 2's job)
- Normalize tone (generation should be authentic, even if slightly clingy)

---

## Layer 2: Polish / Counselor (编辑层)

**Contract output:**

```typescript
type PolishResult = {
  journal: string;         // Final journal content after negotiation
  voiceScripts: Array<{ timing: string; transcript: string; duration: string }>;
  modifications: ModificationLog[];
  blocked: boolean;        // true = content rejected entirely
};

type ModificationLog = {
  rule: string;            // Which polish rule triggered
  before: string;
  after: string;
  action: "replaced" | "truncated" | "rejected" | "passed";
};
```

**Modification rules (applied in order):**

### Rule 1: Sensitive Content → Replace
- Pattern match on `SENSITIVE_PATTERNS`
- Action: Replace offending phrase with safe alternative
- Example: "借钱" → "最近有点经济压力"
- Log: `before`, `after`, `action: "replaced"`

### Rule 2: Journal Length → Negotiate
- If journal > 200 chars: Layer 2 proposes a shorter version
- If journal < 30 chars: reject with `blocked: true`
- Log: `before`, `after`, `action: "truncated"` (not blind slice — end at natural sentence)

### Rule 3: Voice Script Length → Truncate
- If any script > 20 chars: truncate at 20 chars at sentence boundary
- If any script < 5 chars after cleaning: reject that script only

### Rule 4: Tone Boundary → Flag Only
- Detect `CLINGY_PATTERNS` and `PREACHY_PATTERNS`
- Action: Log warning, DO NOT modify content (tone is generation's domain)
- Exception: If both clingy AND preachy detected → reject entire journal

### Rule 5: Duplication → Flag Only
- If > 40% sentences are exact duplicates → log warning, pass through
- Content quality is generation's responsibility

---

## Negotiation Protocol

```
1. Generation returns { ..., raw: true }
2. Polish receives raw content
3. For each modification:
   a. Apply rule in order (sensitive → length → tone → duplicates)
   b. Build ModificationLog entry
   c. Only modify if action is "replaced", "truncated", or "rejected"
4. Return { final journal, voiceScripts, modifications, blocked }
5. If blocked: UI shows "内容生成失败，请重试"
   If not blocked: render with modifications log available for debugging
```

---

## Constraints

- **Generation must always run first** — Polish is read-only on the log
- **At most one rejected item per journal pass** — if blocked, return early
- **Modifications must be reversible** — Log captures `before` and `after`
- **No silent overwrites** — if Polish changes content, UI must be able to show diff

## Exit Criteria

- `polishContent()` returns a `modifications` array with every change
- No content is silently modified without a log entry
- If `blocked: true`, journal is not saved and user sees an error
- All 5 rules produce correct `action` values in the log
